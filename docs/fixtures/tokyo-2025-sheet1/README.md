## 파일 사용법

- [report-fixture.json](report-fixture.json): 정리한 일정·비용·출처·검산 결과. Flutter와 backend의 보고서 테스트에서 공통 입력으로 읽는다.

- 이 README: 사람이 검토할 일정·실제 지출 목록과 해석 규칙.

원본 셀 ID를 사용한 fixture ID는 이 샘플 내부에서만 사용한다. `report-fixture.json`은 보고서 테스트 자료이며 Callable 요청이나 `.trip.json` 복원 파일이 아니다. 셀 문자열은 데이터로 취급하고 새 시트에 쓸 때 사용자 문자열을 수식으로 실행하지 않는다.

## 추출 범위와 해석

- 날짜 열 **8개**(2025-02-02부터 02-09까지), 정리한 일정 **74개**, 별도 일정 변경 메모 **1개**. 귀국편은 2025-02-10 01:55부터 04:40까지다.
- 예상 비용 **73개**, 빈 예산 자리 **31개**, 기록된 실제 지출 **87개**, 별도 원화 수령 메모 **1개**.
- B2:I2의 실제 날짜 값은 **2024년**이다. 문서 제목의 25년 및 일~일 요일이 일치하는 **2025년**을 샘플용으로 해석했다. 원본 연도는 calendarColumns.rawDate와 source-cells.json에 보존한다.
- A열은 06:00부터 다음 날 05:00까지이며 오후 시간을 1:00, 2:00처럼 적었다. `grid`는 이 시간표 위치다. 실제 시간이 명시된 두 항공편만 startTime/endTime이 있고, 나머지는 null이다. 렌더링 테스트는 grid를 사용하고 앱 입력용으로 변환할 때는 시간표 시간을 확정 시각으로 오인하지 않는다.
- 같은 장소가 연속 반복되거나 문장이 나뉜 셀은 묶었다. 빈 색상 블록은 source-cells.json에 남기며 임의의 체류 종료 시간을 만들지 않는다. 원본의 물음표·오타는 보존한다.
- 원본에는 A/B 구분이 없어 샘플의 planId만 A로 지정했다. 장소 링크는 그대로 보존하고 주소·좌표·방문 완료 여부를 만들지 않았다.
- 실제 지출에서 엔 표시가 없는 값은 같은 장부의 JPY 문맥으로 해석하고 currencyBasis에 명시했다. I열 지출에는 날짜 헤더가 없어 2/9 열 위치를 사용했다.
- 결제자·분담 참여자·분담 방식은 미확정이다. 보고서/내역 표시 테스트에는 사용할 수 있지만, 공동 정산 테스트에는 별도의 명시적인 합성 참여자·분담 데이터가 필요하다.
- 예약 가격 18,000 KRW·22,000 KRW, 예상 비용, 실제 지출, 12,000 KRW 수령 메모를 각각 보존하며 서로 합산하지 않는다.
- 첫 탭의 짐·준비물·쇼핑 메모는 source-cells.json에 보존했다. 댓글·사진·그리기 개체는 추출 대상이 아니다. 지도 링크는 외부로 열거나 좌표 조회하지 않았다.
