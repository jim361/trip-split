# 작업 중단 계약 템플릿

반복 작업이나 자율 수정은 시작 전에 아래 네 칸을 채운다. 이 문서는 작업을 무제한으로 계속하기 위한 허가서가 아니다. 달성·탈출·금지 조건 중 하나가 충족되면 기록을 남기고 멈춘다.

## 1. 달성 조건

성공을 검증할 수 있는 결과를 한정한다.

- 목표 결과:
- 성공 verifier:
- 통과 기준:
- 최대 시도 횟수:
- 최대 시간:

나쁜 목표 예시:

> 앱을 완벽하게 다듬을 때까지 계속 수정한다.

좋은 목표 예시:

> `npm run test:emulator`가 현재 규칙 테스트를 통과하고, 두 익명 사용자의 공유·멤버십 시나리오가 재현되면 멈춘다. 최대 3회 시도한다.

## 2. 탈출 조건

다음 중 하나면 더 고치지 않고 상태를 보고한다.

- 동일한 verifier 실패가 최대 시도 횟수만큼 반복됨:
- 요구사항·구현·결정 문서 사이의 충돌로 선택이 필요한 상태:
- 사용자 선택, 권한, 외부 서비스 상태가 없으면 진행할 수 없음:
- 작업 범위를 벗어나는 파일·서비스·배포 변경이 필요함:

## 3. 금지 조건

- verifier를 통과시키려고 테스트, fixture, 보안 규칙, 완료 조건을 먼저 약화하거나 수정하지 않는다.
- 현재 범위에 없는 배포, push, PR 생성, 실제 Firebase 프로젝트, secret 등록, 유료 외부 API 호출을 추가하지 않는다.
- 실패 원인을 숨기기 위해 오류를 무시하거나 성공으로 표시하지 않는다.
- 동일한 실패를 기록 없이 반복하지 않는다.
- “끝날 때까지”, “무제한”, “무조건 통과”처럼 종료 기준이 없는 작업은 시작하지 않는다.
