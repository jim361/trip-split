# Google Sheets 여행 보고서 내보내기

> 2026-09-14. 사용자 요청으로 정리한 개발 방향과 고정 샘플 인계다. 현재는 샘플·문서만 준비됐으며 내보내기 화면, 시트 생성 코드, 실제 Google 연결은 미구현이다.

실행 단계: 고정 샘플 양식·미리보기는 사용자 담당으로 Phase B(P0)와 병행할 수 있다. 기존 데이터·정산 연결 뒤 Google OAuth·실제 생성을 검증하며 B/C 출시 통과 조건으로 추가하지 않는다. 기존 시트를 앱에 가져오는 기능은 별도 후속 후보다. 공통 통합 확인을 우선하고 [단계별 개발 안내](development-kickoff.md)를 따른다.

## 담당과 구현 경계

시트 내보내기는 사용자(Flutter·공통·통합)가 담당한다. 기존 repository로 일정·장소·지출·참여자를 읽고, 기존 Dart 정산 결과를 재사용해 Flutter service에서 보고서의 값과 서식을 만든다. 사용자 Google 계정의 OAuth 권한으로 Google Sheets API에 새 문서를 생성한다.

정산·영수증 백엔드에 보고서 생성을 추가하는 앞선 분담 제안은 채택하지 않는다. 두 백엔드 담당은 기존 일정·지도와 정산·영수증 영역을 유지하며 데이터 계약 변경이 필요할 때만 조율한다. 시트 출력을 위한 새 Firebase Callable·Firestore 컬렉션·서버 집계 로직은 현재 필요하지 않다.

```text
내보내기 옵션 선택
  → 기존 repository에서 필요한 데이터 전체 조회
  → 출력용 데이터 사본 구성
  → 기존 Dart 집계 + 보고서 배치·서식 구성
  → 미리보기
  → Google 계정의 시트 생성 권한 확인
  → Google Sheets에 새 문서 생성
  → 생성된 시트 열기
```

- Widget/controller는 Google Sheets SDK나 HTTP를 직접 호출하지 않고 내보내기 service를 사용한다.
- 파일 백업용 `TripExportPayload`의 도메인 매핑 구조는 참고하되 기존 `.trip.json` schemaVersion·복원 계약은 유지한다. 보고서용 서식·옵션을 백업 스키마에 섞지 않는다.
- `settlement_engine.dart`의 통화별 결제액·부담액·송금 제안을 재사용한다. 서버에 같은 계산을 다시 구현하지 않는다.
- 모든 요청 데이터가 준비되기 전에 비어 있는 목록으로 내보내지 않는다. 출력용 사본을 만든 뒤에는 시트 생성 도중 갱신된 UI 데이터와 섞지 않으며 생성 기준 시각을 표시한다. 이 사본은 여러 Firestore 컬렉션의 원자적 시점 조회를 보장하는 계약은 아니다.

## 첫 구현 범위

- 선택한 날짜·A/B안의 일정과 여행 전체 지출을 표시한다. 일정 필터 때문에 항공·숙소 선결제 또는 일정에 연결되지 않은 지출이 빠지면 안 된다. 여행 기간 밖의 선결제는 별도 영역에 표시한다.
- 여행 기간에 맞게 날짜 칸을 확장하고, 지출 건수·긴 제목/메모에 맞게 행과 높이를 확장한다.
- 시간 없는 일정과 장소 없는 일정도 보존한다. 시간 미정 영역에서 저장된 순서를 사용하며 장소 연결은 선택 사항이다.
- 지도 링크를 포함하고 기존 장소명·일정 순서를 사용한다. 이동 시간·GPS 경로·실제 방문 완료 여부를 추정하지 않는다.
- 지출 금액은 숫자로, 통화는 별도 필드로 다룬다. 통화별 합계를 유지하고 임의 환산하지 않는다.
- 예약은 준비 정보이며 결제된 비용은 기존 지출 원장을 기준으로 한 번만 합산한다. 영수증 품목과 지출 총액도 중복 합산하지 않는다.
- 버튼을 누른 시점의 새 보고서를 만든다. 양방향 동기화·기존 시트 덮어쓰기·백그라운드 정기 생성은 첫 구현 범위가 아니다.
- 취소·권한 거부·오프라인·저장 실패·중복 제출을 처리한다. 생성 응답이 유실되면 무조건 새 문서를 만드는 자동 재시도는 하지 않는다. 문서 ID를 받은 뒤 내용 쓰기가 실패하면 해당 ID를 유지해 복구한다.

## Google 연결

현재 `FirebaseAuthService`는 Google ID token으로 Firebase 계정을 연결한다. Sheets API 접근 토큰을 발급받거나 시트 생성 권한을 요청하는 구현은 아직 없다.

내보내기 시 사용자 동작으로 `drive.file` 범위의 권한을 요청하고 승인된 접근 토큰으로 시트를 만든다. Firebase 로그인 성공만으로 이 권한이 있다고 판단하지 않는다. 앱에 service account 비밀키나 OAuth client secret을 넣지 않는다.

실제 연결 전 Google Cloud의 Sheets API·Android OAuth 설정이 필요하다. 운영 프로젝트 설정·권한 동의·외부 생성은 별도 연결 단계에서 처리하며 이번 커밋은 해당 작업을 수행하지 않는다.

참고: [Google Sheets 생성 API](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/create), [파일별 접근 범위](https://developers.google.com/workspace/sheets/api/scopes), [Flutter Google 추가 권한 요청](https://pub.dev/packages/google_sign_in#authorization).

## 고정 샘플 사용 시 주의

- 원본 날짜 셀은 2024년이지만 문서 제목과 요일을 근거로 샘플 날짜를 2025년으로 해석했다. 원본 값은 보존했다.
- 8개 날짜 열은 2/2부터 2/9까지이며 마지막 열의 귀국편은 2/10 01:55~04:40이다.
- 시간표 위치는 `grid`, 직접 적힌 항공편 시간은 `startTime/endTime`이다. 위치만 있는 항목의 시각을 확정 사실로 변환하지 않는다.
- 실제 지출 87건의 상세 합산은 93,631 JPY, 원본 일일 합계 합산은 91,546 JPY, 원본 전체 합계는 92,146 JPY다. 어느 값을 최종 정산으로 확정한 자료가 아니다.
- 샘플의 예약 가격·예상 비용·실제 지출·원화 수령 메모는 각각 보존한다. 이는 앱에 예산·정산 완료 기능이 이미 있다는 뜻이 아니다.
- 결제자·분담 참여자가 충분히 명시되지 않아 공동 정산 결과는 만들지 않았다. 정산 출력 검증에는 기존 canonical fixture 또는 별도로 명시한 합성 분담 데이터를 사용한다.
