# 정산·영수증 기능 논의

> **[회의 02 · 정산·영수증 기능 후보]** `ST`와 `OCR` 기능 ID를 논의합니다.

[논의 홈](README.md) · [일정·지도](itinerary-map.md) · **정산·영수증**

여행 생성 시 잡은 예상 인원을 실제 정산 참여자로 관리하고, 여행 전 예약비부터 현지 지출과 영수증까지 하나의 원장에 기록하는 흐름을 다룬다. 솔로 여행도 같은 원장을 사용하되 송금 제안 대신 개인 소비 내역을 중심으로 보여주는 것이 현재 기본안이다.

Android 구현 순서 후보는 P0 수동 `equal/custom`·validator·통화별 계산, P1 `itemized`·영수증 촬영·OCR·번역이다. 첫 배포 포함 범위는 아래 `논의중` 항목을 회의에서 확정하며 한 PR에서 동시에 만들지 않는다.

```text
예상 인원 생성 → 지출 입력 또는 영수증 검토 → 사람별 배분 → 개인 소비 확인 → 통화별 송금 제안
```

| ST-12  | 개인 소비 내역과 송금 문구를 제공한다              | 카테고리·날짜·장소·메뉴별 소비와 최종 송금을 확인·복사한다                         | 논의중 | 솔로 여행은 소비 내역만 강조                    |
| ST-13  | ISO 통화 코드별로 따로 집계·정산한다               | 환율을 정하지 않아도 서로 다른 금액을 잘못 더하지 않는다                           | 논의중 | 첫 fixture는 KRW·JPY, 화면에 `환율 미적용` 표시 |
| ST-14  | 지출 변경을 다른 멤버에게 실시간 반영한다          | 단체 여행에서 모두 같은 원장과 계산 결과를 본다                                    | 논의중 | 별도 정산 snapshot은 만들지 않음                |
| OCR-01 | 인증된 멤버만 `parseReceipt`를 호출한다            | Android 카메라·Photo Picker 이미지를 보내기 전에 권한·형식·크기를 검사한다         | 논의중 | 실제 OCR provider는 일본어 fixture 검증 후 결정 |
| OCR-02 | 원문·번역 OCR 결과를 수정 가능한 초안으로 보여준다 | source language, 원문·한국어명, 통화·금액·confidence를 비교하고 누락 행을 추가한다 | 논의중 | 번역은 이해 보조, 금액은 이미지·원문 기준       |
| OCR-03 | 사용자가 확정한 뒤에만 지출을 저장한다             | 잘못 인식한 내용이 정산에 자동 반영되지 않는다                                     | 논의중 | 이미지·원문·미확정 초안은 영구 저장하지 않음    |
| OCR-04 | OCR 실패 시 총액 기반 수동 등록으로 전환한다       | 외부 API가 실패해도 지출 등록을 끝낼 수 있다                                       | 논의중 | equal/custom 분할 재사용                        |
